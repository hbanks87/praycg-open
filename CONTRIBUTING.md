# Contributing to PRAYCG

PRAYCG welcomes software contributions, reproducible research, critical review and negative results. The Workbench and the Neuro Research Program have related but distinct contribution routes.

## Workbench contributions

Start with [development orientation](workbench/development/README.md). Useful contributions include:

- Acquisition reliability, stream metadata and timing checks.
- Clearer setup, recovery and analysis workflows.
- Tests using synthetic data and explicit failure cases.
- Reproducible analysis, environment descriptions and bundle verification.
- Hardware route documentation with precise device and validation boundaries.
- Accessibility, documentation and attribution corrections.

Identify the exact application version and entry point affected. Repository rearrangement does not change the versioned application ZIP. Do not quietly mix new development source with historical release evidence.

## Research contributions

Start with the [Research Program](research/README.md), [theory index](research/theory/README.md) and [protocols](research/protocols/README.md).

Useful contributions specify a falsifiable question, an operational definition, a competing explanation, a confound control, a prospective study plan or a reproducible reanalysis. Distinguish exploratory and confirmatory work and report missing estimates or negative results honestly.

Theory documents are part of the project's historical record. Propose a new version, correction note or clearly reviewed change; do not silently replace or remove the original. An implementation is not proof of a proposed mechanism.

## Evidence and privacy

Provide the smallest useful reproduction, preferably synthetic. Public issues and pull requests must not contain participant recordings, credentials, private identifiers, unreviewed personal material or stimuli you lack permission to redistribute.

Do not claim that PRAYCG demonstrates consciousness, clinical efficacy, cellular memory, quantum mechanisms or metaphysical conclusions merely because a tool runs or an exploratory output changes.

## Source and attribution

Identify upstream sources, exact versions or commits, applicable notices and material modifications. Preserve original notices. Citation and software availability do not by themselves establish permission or scientific validity.
