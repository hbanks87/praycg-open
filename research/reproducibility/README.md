# Reproducibility and replication

This hub catalogs artifact-bearing synthetic reproduction kits, the NUPI reanalysis companion and human replication plans in PRAYCG's public research tree. Other analysis definitions are indexed under [measures](../measures/README.md) and [protocols](../protocols/README.md). A runnable script, an internal replay and an independent replication establish different things. This index does not rerun the analyses or change the status of their original evidence.

## Run and verify the external handoff

Use the full preserved `Rung0K_ExternalReproducibilityHandoff` directory. Its [start guide](../studies/optoping-rung0/Rung0K_ExternalReproducibilityHandoff/00_README_START_HERE/README_RUNG0K_EXTERNAL_REPRODUCIBILITY_HANDOFF.md) specifies Python 3.10 or later and the required dependencies. From `02_REPRODUCTION_SCRIPT`, run:

```text
python -m pip install -r requirements.txt
python run_osm_opto_ping_rung0j_preregistered_lockin_v0_1.py --out-dir reproduced_outputs
python ../07_UTILITIES/verify_external_rung0j_results.py reproduced_outputs
```

Keep the locked specification, seed policy, model alternatives and pass/fail criteria unchanged. The verifier checks the declared specification hash and summary criteria; it does not require byte-identical CSV formatting. The package also retains its [file inventory](../studies/optoping-rung0/Rung0K_ExternalReproducibilityHandoff/00_README_START_HERE/FILE_INDEX.csv), [checksums](../studies/optoping-rung0/Rung0K_ExternalReproducibilityHandoff/00_README_START_HERE/SHA256SUMS.txt) and [saved verification output](../studies/optoping-rung0/Rung0K_ExternalReproducibilityHandoff/04_CLEANROOM_REPLAY_RESULTS/verification_output.json).

Preserve the new output directory, verification output, Python/package versions, operating system, command and deviation notes. Complete the [external reporting template](../studies/optoping-rung0/Rung0K_ExternalReproducibilityHandoff/05_EXTERNAL_REPORT_TEMPLATE/REPORTING_TEMPLATE.md). The [handoff report](../studies/optoping-rung0/Rung0K_ExternalReproducibilityHandoff/06_REPORT/OSM_OptoPING_Rung0K_ExternalReproducibilit__cb5cf14b.md) defines `EXTERNAL_PASS` and `EXTERNAL_FAIL` separately from the internal replay. An independent result needs its own identified record.

For 0O, follow its own [run instructions](../studies/optoping-rung0/Rung0O_LockedNullAwareReproduction/README_RUNG0O.md) and inspect its generated decision table and pass summary against the frozen 0O specification. The 0J verifier is specific to 0J; its criteria do not grade 0O.

## Human replication and proposed programs

The [master theory and protocol v1.1](../theory/originals/docs/PRAYCG_Master_Theory_and_Protocol_PUBLIC_v1_1_v095.md#28-prospective-study-roadmap) proposes four stages: software/hardware reproducibility, individual replication, small-N feasibility and a prospective group study. Its [replication gate](../theory/originals/docs/PRAYCG_Master_Theory_and_Protocol_PUBLIC_v1_1_v095.md#277-replication-gate) calls for repetition across stimuli, sessions and participants without post-hoc tuning, ideally with external operators. These are study requirements and plans, not declarations that the stages are complete.

The preserved [prospective PRAYCG3/PRAYCG4 package v0.1 specification](../protocols/originals/docs/PRAYCG_v0_93_to_v0_95_Protocols_Theory_and_Analysis_Methods.md#6-prospective-praycg3praycg4-package-v01) documents six PRAYCG3 and four PRAYCG4 fixed order variants, independent validity outcomes and frozen input identities. Its [readiness boundary](../protocols/originals/docs/PRAYCG_v0_93_to_v0_95_Protocols_Theory_and_Analysis_Methods.md#66-current-readiness-boundary) explicitly requires further stimulus, anchor, ethics/consent, apparatus, feasibility and registration work before collection. A documented design is not a completed prospective study.

The same supplement documents [CAI/SID v0.2](../protocols/originals/docs/PRAYCG_v0_93_to_v0_95_Protocols_Theory_and_Analysis_Methods.md#4-caisid-v02--controlled-access-integration-index), including its [retrospective future-slow component](../protocols/originals/docs/PRAYCG_v0_93_to_v0_95_Protocols_Theory_and_Analysis_Methods.md#44-retrospective-future-slow-value). It is an exploratory method definition to preserve when reproducing a historical analysis; it is not a new independent replication record or a validated consciousness measure.

Use the [ladder index](../ladders/README.md), [protocol index](../protocols/README.md) and [research roadmap](../roadmap.md) to identify the relevant design and claim boundary. The [Contact self-run](../studies/contact-pilot/README.md) and [versioned pilot reports](../studies/reports/README.md) retain exploratory evidence and their original limitations. Replaying their analysis does not create a new participant sample or a prospective replication.

The Workbench's [development guidance](../../workbench/development/README.md) describes software checks and release evidence. Package hashes, installation checks, synthetic regression and physical timing checks each retain their stated scope; none alone demonstrates a replicated scientific effect.

## Preserve source identity and report limitations

Record the exact source version, inputs, lock/specification hashes, environment, outputs and any deviations. Keep a reproduction of the frozen method separate from a modified analysis. Report missing inputs, changed dependencies and failed criteria explicitly. The preserved requirements files do not all pin exact package versions; retain the actual environment used.

Scientific originals keep their historical paths and bytes. Use the [original-file locator](../../docs/reorganization/original-file-index.md) to resolve an old path, particularly for NUPI's source layout. Read the [public data boundary](../ethics-and-claim-boundaries/originals/public_data_boundary.md) before sharing results. The source documents and artifact-specific terms govern reuse; this hub adds navigation rather than new validation.
