## Retained Alpha 11.3.2

- Hardens guided QC, recommended analysis and explicit **Run pending analyses** handoffs. Expected, verified analysis derivatives are distinguished from changed source data; integrity checks are not bypassed.
- Moves expensive refresh, history and report work off the interface thread, rejects stale results and guards against duplicate workflow entry. Historical stop/failure records remain visible without becoming the current run's status.
- Repairs a fast-completion race that could leave the verification window waiting indefinitely. Between-module checks wait for finalized receipts; short Windows file-sharing conflicts receive bounded retries without discarding the previous receipt.
- Automatic queues verify their next step in the background instead of entering nested waiting dialogs. Each approval is single-use and bound to the current selection; cancellation, changed inputs and failed checks stop the handoff.
- Reads authenticated Signal Review endpoint status from its attempt folder, so a successful tool run is not mistaken for an available measurement.
- Keeps **Create / view local numerical summary**, saved AI explanations and a new **Generate AI explanation** request distinct. Partial reporting is deliberate and identifies pending, failed, skipped and unavailable work; successful execution does not guarantee an estimable endpoint.
- Adds **Settings → Updates**: explicit release checks, verified preparation, signed offline ZIP import, update/restart, compatible previous-version recovery, logs and an edition-specific stable desktop shortcut.
- Verifies Ed25519 signatures using the included public trust key and checks archive hashes, edition, versions, state compatibility and safe extraction. Installs beside the current version, snapshots settings before first launch and switches the stable launcher only after the new interface reports readiness.
- Blocks restart during active acquisition, analysis, preparation, provider requests or local exports. External LabRecorder must be stopped and saved. No active process is automatically killed.
- Reuses a verified existing Zuna runtime/model binding only when its pinned contract matches. Ordinary updates do not redownload model weights or replace recordings, historical results or assistant history.

The first installation remains a manual extraction into a new directory. No remote signed release was published during this build; remote checking cannot install a release until its signed metadata is available. Offline import needs both the ZIP and its `.update.json` sidecar; dependency setup may still require internet access or cached packages. Test coverage includes simulated installers/failures, actual application constructors and a real Zuna binding verification, not a fresh-machine installation certification. See [BUILD_REPORT.md](BUILD_REPORT.md) for final evidence and limits.

## Retained Alpha 11.3.1 responsiveness and report handoff

This hotfix targets repeated eligibility checks while searching, slow synchronous refresh work, and confusing report selection. Module searches use the loaded view, background refreshes reject stale results, and execution-time integrity checks remain in place. Report opening distinguishes the latest saved AI explanation from the local numerical summary. New explanation requests carry source-linked findings, not just eligibility labels; historical reports are not rewritten. Opening a saved draft does not mark it human-reviewed or scientifically validated. Generating a new AI explanation remains a separate, explicitly authorized request.

Read [BUILD_REPORT.md](BUILD_REPORT.md) for the completed verification scope. Existing recordings, historical results, settings and Zuna assets are not migrated or replaced by this package. Use a new release folder; do not merge it over an older installation. No acquisition-quality threshold or scientific estimator is relaxed by this responsiveness work.
