# AI-assisted authoring boundaries — Alpha 10.1.0

The current public README supplies operator instructions. This reference distinguishes supported authoring paths and remaining development work. No PRAYCG authoring action automatically uploads data or contacts an AI provider.

## Supported paths

| Intent | Returned artifact | Supported endpoint |
| --- | --- | --- |
| Compose a protocol from bounded implemented task components | PRAYCG_DataOnlyProtocolExtension_v1_0 JSON, with request/parent origin when AI-assisted | Verify original request, validate, run bounded fake-I/O rehearsal, review locally and explicitly install in My Protocols. Normal materials, hardware and acquisition gates remain. |
| Propose a wider Atlas or native design | Legacy Atlas/native candidate JSON and design review | Structural review and immutable staging only; not runtime installation. |
| Revise permitted settings of an existing EEG method | Parent-bound EEG recipe proposal JSON | Review differences, load into the form, validate and lock a new recipe. No new estimator is installed. |
| Add a new engine, hardware operation or algorithm | Separately reviewed software extension proposal and tests | Development work; not accepted through the casual-user importer. |
| Return externally analyzed study results | Results-return ZIP, its manifest and original exported study | Verify/stage untrusted outputs separately. No returned code executes and no existing results are overwritten. |

## Data-only protocol admission

The contract is smaller than the internal Atlas schema. It accepts enumerated task kinds, typed bounded controls actually consumed by the timeline, declared media keys, semantic hardware roles and existing analysis templates. It rejects unknown/custom fields, unsupported behavior, duplicate or nonfinite JSON, excessive expansion, unsafe file identities and executable bindings.

The trusted compiler selects the packaged engine and shared runner. A definition cannot select arbitrary scripts, download dependencies, control devices or install analysis code. Required QC and existing continuous EEG methods retain their real input requirements. Event declarations do not manufacture observations or make native PRAYCG-specific metrics applicable to unrelated tasks.

My Protocols keeps data outside the application. Installation preserves an immutable definition, compiled manifest, receipt and rehearsal. Active-version changes affect future discovery; historical locks resolve their exact identity. Damaged entries are visibly excluded. Engine/runner fingerprints are exact: changing executable code requires explicit compatibility review/re-admission, not automatic receipt editing or silent migration.

## The AI round trip

The outgoing pack contains the extension schema, release-bound capabilities and a software-format example. Original document-set and design-revision hashes bind the return. PRAYCG independently verifies the original ZIP's exact ledger and bytes. A matching hash is identity evidence, not proof of scientific merit or authorship by a particular model.

The review displays requested and returned design fields. Malformed returns, stale requests and unsupported features require correction; a bounded repair request preserves original identity. AI-provided approval and claimed tests grant nothing. A local person explicitly decides on installation after reviewing the actual checks.

The local template form is an alternative without an external AI. Examples must be adapted and reviewed; their presence does not validate a research question.

## What rehearsal establishes

The bounded rehearsal uses actual task dispatch, clock/wait, response and media-handler paths with fake I/O. It checks finite execution, event/response production and supported handling. It does not display actual stimuli, decode later-selected media, measure optical/acoustic onset, connect devices or establish participant safety. Rehearse with the intended materials and apparatus before participant acquisition.

Run-local extension evidence is retained for analysis/private-context bundles. Import keeps it as inert provenance and does not install or activate it. Privacy exclusions remain effective; a results-only bundle does not assure that all original context or raw inputs were included.

## Remaining milestones

Broader analysis templates and new numerical methods, additional physically tested equipment, independent second-machine replay, public catalog governance and executable extension isolation remain separate milestones. This importer must not bypass those requirements.

Software acceptance differs from scientific support, ethics/consent review, physical timing and clinical validation. Hypothesis-generating protocols remain exploratory; an AI model/version is provenance, not an approval tier.
