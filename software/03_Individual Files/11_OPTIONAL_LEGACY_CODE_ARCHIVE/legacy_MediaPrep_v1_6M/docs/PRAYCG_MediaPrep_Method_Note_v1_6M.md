# PRAYCG MediaPrep Method Note v1.6M

## Purpose

PRAYCG MediaPrep v1.6M standardizes stimulus preparation for the three-arm PR-AYC-G protocol.

The three prepared files should correspond to:

1. Phase-scrambled control
2. Target / natural viewing
3. Contextual Override / analytic running-sum task

## Preparation logic

The tool starts from one master `.mp4` and creates a cue-embedded version of the target. That cued target is copied byte-for-byte into the contextual override video. The target and override are therefore physically matched at the file level.

The control is then generated by phase-scrambling the cue-embedded target.

This creates the intended contrast:

```text
Control:
  sensory/cue timing with narrative structure removed

Target:
  intact narrative, numbers ignored

Contextual Override:
  same intact narrative, same numbers, running-sum task
```

## Cue design

Default cue design:

```text
values: 1-10
interval: every 3 seconds
display duration: 0.85 seconds
position: upper_right
start delay: 3 seconds
```

The cue is displayed as a contrast-protected badge rather than plain white text. The badge uses a semi-transparent dark rectangle, pale border, black text outline, and white number. This reduces cue-visibility failure on bright scenes while preserving a fixed position to minimize visual search and eye-movement artifacts.

## Why fixed position is retained

A moving cue would create a separate visual-search task. Fixed upper-right placement keeps the arithmetic task spatially stable. That helps distinguish arithmetic / working-memory lock from saccade/search artifacts.

## Cue visibility

The schedule records cue timing, value, expected sum, badge region, and local background-luminance estimates. Exact arithmetic correctness should be interpreted with cue visibility, subjective task effort, and task leakage.

A wrong sum may indicate:

- poor engagement,
- working-memory error,
- cue visibility dropout,
- narrative leakage,
- fatigue,
- or a mixture.

It should not automatically be treated as noncompliance.

## Phase scrambling

Video frames are phase-scrambled by applying a 2D FFT to each frame/channel, preserving magnitude approximately and randomizing phase. Audio is phase-scrambled locally by STFT, preserving local spectral magnitude while randomizing phase.

The goal is to destroy recognizable narrative structure while preserving a rough sensory-delivery clone. This is a control-generation tool, not a guarantee of perfect physical equivalence. Run StimulusFingerprint QC afterward.

## Required downstream QC

After media prep, run StimulusFingerprint v1.5 to assess:

- duration match,
- FPS match,
- resolution match,
- luminance profile,
- visual-change profile,
- audio dBFS profile,
- cue visibility,
- target-control physical-match score.

## Empirical boundary

Media preparation does not establish a PR-AYC-G effect. It only prepares the stimulus suite for acquisition. Interpretation requires physiological data, event markers, respiration, artifact handling, self-report, and master-suite analysis.
